# 화면 전환 스켈레톤 로딩

## 개발 목표와 의도

> "모두의입법의 모든 화면 전환에서 필요한 곳에 스켈레톤 애니메이션을 적용하자"

지금은 화면이 바뀌는 동안 보이는 것이 제각각이다. 피드의 법안 카드를 눌러 법안 상세로 가면 서버 응답이 올 때까지 이전 피드가 그대로 멈춰 있어서 눌렸는지 알 수 없다. 탐색의 국회 탭은 "의석 분포 불러오는 중…" 같은 문구가 떴다가 큰 차트로 바뀌어 화면이 덜컥 밀린다. 법안 목록 아래 무한 스크롤은 회색 스피너를 쓴다.

이번 작업은 화면이 바뀌는 순간 곧 나타날 화면의 뼈대(제목 줄, 카드, 아바타 자리를 회색 블록으로 그린 자리표시, 이하 "스켈레톤")를 먼저 보여 주고, 자료가 오면 같은 자리에 내용이 채워지게 한다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
|---|---|---|
| 라우트 이동 스켈레톤 | 법안 상세, 의원, 정당, 리포트, 검색, 타임라인, 탐색, 분야별 법안, 알림, 마이페이지, 팔로잉으로 이동하면 머리글은 남고 본문 자리에 그 화면 모양의 스켈레톤이 바로 뜬다. | 링크를 눌러도 이전 화면이 멈춰 있으면 사용자가 다시 누르거나 앱이 멈췄다고 생각한다. |
| 섹션 첫 로딩 스켈레톤 | 피드 카드, 탐색의 분야 카드·인기 키워드·의석 분포·발의 순위·의원 목록·정당 목록, 의원·정당 프로필, 다른 개정안, 알림, 마이페이지·팔로잉 섹션이 불러오는 동안 실제 카드와 같은 크기의 스켈레톤을 보여 준다. | 문구에서 큰 콘텐츠로 바뀌면 화면이 아래로 밀려 읽던 위치를 잃는다. 같은 크기의 자리를 먼저 잡으면 밀림이 없다. |
| 무한 스크롤 다음 페이지 스켈레톤 | 법안·의원 목록을 끝까지 내리면 스피너 대신 카드 스켈레톤이 목록 끝에 붙는다. | 스피너는 무엇이 올지 알려 주지 않는다. 카드 모양이 이어지면 목록이 계속된다는 것을 바로 안다. |
| 통계 탭 스켈레톤 통일 | 통계 카드가 쓰던 별도 회색 블록을 공용 스켈레톤으로 바꾼다. | 같은 앱에서 스켈레톤 색과 동작이 두 가지로 보이지 않게 한다. |

## 개발 목표

- 피드에서 법안 카드의 "자세히 보기"를 누르면 머리글 아래에 법안 상세 모양의 스켈레톤이 바로 보인다.
- 탐색 → 국회 탭을 열면 의석 분포, 발의 순위, 의원 카드 자리가 스켈레톤으로 먼저 잡히고, 자료가 와도 아래 내용이 밀리지 않는다.
- 법안 목록을 끝까지 내리면 스피너가 아니라 카드 스켈레톤이 보인다.
- 운영체제에서 "동작 줄이기"를 켜면 스켈레톤이 깜박이지 않고 고정된 회색으로 보인다.
- 화면 읽기 프로그램은 스켈레톤마다 "불러오고 있습니다" 안내를 한 번 읽는다.

## 범위 밖과 제약

- 버튼의 "삭제 중…", "탈퇴 처리 중…"처럼 누른 동작의 진행 표시는 그대로 둔다. 화면 전환이 아니다.
- 소셜 로그인 콜백의 "로그인 상태를 확인하는 중입니다" 문구는 그대로 둔다. 내용이 아니라 절차 안내다.
- 질문하기 화면의 답변 준비 표시는 이미 스켈레톤을 쓰므로 건드리지 않는다.
- 타임라인 화면 구성(48c52a4 기준)은 바꾸지 않는다. 스켈레톤만 그 구성을 따른다.
- 새 애니메이션 라이브러리나 모션 토큰을 들이지 않는다. 기존 펄스(`animate-pulse`)를 쓴다.

## 열린 질문

없음. 적용 범위(라우트 이동, 섹션 첫 로딩, 무한 스크롤 모두)는 2026-11-08 사용자가 정했다.
