# 법안 재수집과 최신 발의자 정보 복구

## 개발 목표와 의도

“실제 사용자가 모두의입법의 모든 화면을 완성 제품 품질로 느끼게 만든다”는 목표에 따라 W1 수집 복구의 선행 결함을 수정한다. 운영 목록은 7월에 멈춰 있다. 11월 2일 하루를 읽기 전용으로 수집해도 29건 모두 발의자 관계를 확보하지 못해 제외됐다. 같은 공식 국회 화면에는 해당 법안과 발의자 명단이 있다. 재수집 코드는 기존 AI 요약과 제목까지 덮어쓸 수 있어, 자동 수집을 켜기 전에 수정해야 한다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
| --- | --- | --- |
| 공식 발의자 명단 보완 | API에 명단이 없을 때 국회 공식 화면에서 전체 명단과 명시된 대표발의자를 확인한다. 인물 매칭이 불확실하면 제외 사유를 유지한다. | 최신 법안이 API 갱신 차이로 영구 누락되는 것을 줄인다. |
| 대표발의자 역할 보존 | 확인한 대표발의자 ID를 목록의 순서와 분리해 사용한다. | 첫 번째 공동발의자를 대표발의자로 잘못 표시하지 않게 한다. |
| 재수집 시 AI 결과 보존 | 원문 수집에 AI 값이 없으면 기존 AI 요약·제목·태그를 유지한다. | 반복 수집으로 사용자가 읽던 요약이 사라지는 것을 막는다. |
| 의원 명부의 안전한 동기화 | 누락 의원의 추가와 전체 명부 교체를 구분하고, 전체를 받은 경우에만 현직 상태를 변경한다. | 29건의 법안에 필요한 의원 코드 1개가 운영 DB에 없다. 단건 추가로 다른 의원이 비활성화되는 것을 막아야 한다. |

## 개발 목표

- 같은 법안을 두 번 수집해도 기존 AI 콘텐츠와 조회수가 보존된다.
- 공식 표본에서 확인한 10명의 전체 명단과 대표발의자를 실제 ID로 매칭한다.
- 불완전한 명단·모호한 인물·대표발의자 누락을 성공으로 처리하지 않는다.
- 격리 DB와 dry_run으로 확인한 뒤 운영 반영을 별도로 승인받는다.

## 범위와 승인

W1의 수집 선행 수정이다. 백필·AI 생성·분야/표결 갱신·timer 등록은 후속 운영 절차로 이어간다. 운영 DB 쓰기와 timer 등록, PR 머지는 실행별 승인 대상이다. 사용자의 5단계까지 intent 자동 수락 지시를 적용했다.

## 열린 질문

없음. 공식 화면에서 증명할 수 없는 관계는 기존 미해결 경로로 남긴다.
