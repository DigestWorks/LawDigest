# 모두의입법 1차 핵심 화면 복구

## 개발 목표와 의도

“실제 사용자가 모두의입법의 모든 화면을 완성 제품 품질로 느끼게 만든다.”

승인된 handoff의 1차 묶음 W5, W6, W3 웹 부분, W11 일부를 진행한다. 운영 화면에서 의료법 검색 결과가 스크롤 후에도 5건에 머물고, 다크 모드 피드 탭은 읽기 어렵다. 검색 API는 한 글자와 괄호 포함 입력에 500을 반환한다. 사용자가 목록을 이어 읽고, 검색하고, 법안의 현재 상태를 정확히 확인할 수 있게 만든다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
| --- | --- | --- |
| 목록 끝까지 탐색 | 검색·의원·정당 목록을 다음 페이지와 끝 상태까지 읽는다. 피드 필터·탭을 바꾸고 상세에서 돌아와도 해당 목록이 유지된다. | 첫 몇 건만 전체 결과로 오해하거나 다른 조건의 결과를 읽는 문제를 해소한다. |
| 검색 입력과 결과 복구 | 괄호 포함 법안명과 예약문자가 있는 검색어를 처리하고, 잘못된 입력에는 해당 영역에서 안내한다. 법안명·관련도를 반영하며 의원 결과가 법안 결과를 밀어내지 않게 한다. | 흔한 입력으로 전체 화면이 실패하고 무관한 법안이 먼저 나오는 문제를 해소한다. |
| 검색 진입점 통일 | 데스크톱과 모바일이 같은 검색 입력·최근 검색어를 사용한다. 지우기는 입력만 지우며, 검색창을 키보드로 열고 닫을 수 있다. | 화면마다 검색 방법과 저장 동작이 달라지는 혼란을 해소한다. |
| 처리 단계와 결과 구분 | 체계·자구 심사와 정부이송을 정확히 표시하고, 철회·폐기 등 종료 상태를 진행 중 단계와 구분한다. 표결 기록이 없으면 결과와 미수집 상태를 표시한다. | 잘못된 현재 단계와 숫자 없는 표결 차트로 생기는 오해를 해소한다. |
| 다른 개정안 순차 탐색 | 최근 개정안부터 일부를 보여 주고 나머지는 다음 페이지로 읽는다. | 한 상세 화면에서 761건을 한꺼번에 내려받고 그리는 부담을 줄인다. |
| 요약 읽기와 펼치기 | 요약의 제목·문장·용어 풀이를 보조기기로 읽는다. 펼치기와 접기는 별도 버튼으로 조작한다. | 본문 전체가 버튼으로 읽히고 본문 선택 중 펼침이 바뀌는 문제를 해소한다. |
| 다크 모드 피드 탭 | 리포트·법안·팔로잉의 이름과 선택 상태를 어두운 화면에서도 읽는다. | 첫 화면에서 탐색할 탭을 구분할 수 있게 한다. |

## 개발 목표

- 검색·의원·정당에서 두 번째 페이지를 읽고, 마지막 페이지 이후 추가 요청이 멈춘다. 조건을 바꾸면 그 조건의 결과가 나오고 뒤로 가기로 목록 상태를 복원한다.
- 한 글자·공백·괄호·예약문자·음수 페이지 입력으로 전체 화면 500이 발생하지 않는다. 로딩·빈 결과·검색 실패를 구분한다.
- 정부이송·체계자구 심사·철회·가결 후 표결 미수집 표본에서 실제 API 값과 화면 설명이 일치한다.
- 761건 개정안 표본의 첫 응답·렌더링이 일부로 제한되고 나머지를 계속 읽을 수 있다.
- 데스크톱, 모바일 375px, 다크 모드에서 검색·탭·요약의 실제 조작과 키보드 동작을 확인한다.

## 범위와 승인 지점

- 리포트 전용 데이터 계약은 3차 W10에서 구현한다. 리포트 탭과 정당 강조색을 유지한다.
- RAG 출시는 별도 intent로 연결 범위를 확정해 1차 안정화 직후 이어 진행하는 안을 제시한다. 자연어 질문 관련 SEARCH-07, SHELL-03, A11Y-05, TRUST-14는 실제 답변·출처 검증까지 미해결로 추적한다. 문구 교체로 완료 처리하지 않는다.
- W5의 DETAIL-07은 서버 페이지네이션과 메타데이터 보완까지 함께 고쳐야 전송량을 줄일 수 있다. 이 동반 백엔드 수정은 이번 intent에 포함한다.
- W3의 전체 법안 대수 필터·상태 재계산과 표결 백필은 후속 백엔드·W1 작업에서 완료한다. 운영 DB 쓰기와 timer 등록은 실행마다 별도 승인한다.
- 처리방침의 운영 주체·연락처·보관 기준은 모두 미정이다. 2차 W8에서 확인받는다.
- intent 수락 전에는 제품 코드 수정과 아티팩트 커밋을 하지 않는다. 수락 뒤 세 아티팩트를 순서대로 커밋하고 구현한다.

## 열린 질문

2026-11-03 사용자가 5단계까지 모든 intent의 자동 수락을 지시했다. 이 intent와 slug를 수락된 것으로 기록하고, RAG 연결·출시는 1차 안정화 직후 별도 intent로 이어 진행한다. 전체 목표는 5단계까지 유지한다. 운영 DB 쓰기·timer 등록·PR 머지는 별도 승인 지점을 유지한다.
