# 근거 법안을 확인할 수 있는 질의응답 출시

## 개발 목표와 의도

사용자는 “법안 질의응답(RAG) 기능 출시”를 선택했다. 법안명을 몰라도 생활 속 질문으로 관련 내용을 찾고, 답변의 근거 법안과 원문을 확인할 수 있게 한다. 기존 RAG는 Python 모듈과 목 테스트만 있으며 공개 API·웹 호출 경로가 없다. 운영 기본 컬렉션도 없고 다른 법안 인덱스는 2025년 9월 법안 112건에 머물러 있다. 실제 검색·생성·출처·최신성·실패 처리를 연결해야 한다.

## 기능 목록

| 기능 | 설명 | 왜 필요한가 |
| --- | --- | --- |
| 법안 질문과 후속 대화 | 기존 검색 진입점에서 질문 화면으로 이동하고 질문·후속 질문·중지·재시도를 제공한다. | 질문형 안내가 실제로 응답하는 경로가 필요하다. |
| 근거가 연결된 답변 | 답변 문단마다 확인한 근거를 연결하고 법안 상세·국회 원문으로 이동한다. | 사용자가 AI 설명을 검증하고 처리 상태를 확인할 수 있어야 한다. |
| 자료 범위와 기준일 | 기본 22대, 21대·전체 선택과 데이터·인덱스 기준일을 표시한다. | 과거 법안과 수집되지 않은 최신 정보를 현재 법률처럼 오해하지 않게 한다. |
| 근거 부족·실패 구분 | 근거가 없으면 추측 답변을 만들지 않고, 일시 오류·요청 한도·취소를 구분한다. | 실패 문구를 정상 답변으로 읽거나 질문을 잃지 않게 한다. |
| 출시용 인덱스와 서비스 | 기존 AI 모듈을 내부 API로 제공하고 검증된 별도 인덱스를 연결한다. | 작은 실험 인덱스와 목 응답만으로 출시를 판정할 수 없다. |

## 개발 목표

- 실제 질문에서 벡터 검색·현재 원문 대조·생성·출처 이동까지 동작한다.
- 후속 질문과 상세 화면 왕복에서 대화를 유지하며 키보드·375px·다크 모드로 사용할 수 있다.
- 근거가 비거나 출처 ID가 잘못된 생성 결과를 정상 답변으로 표시하지 않는다.
- 출시용 인덱스의 범위·건수·기준일을 확인하고 운영 화면에서 실제 답변을 검증한다.

## 제약과 승인

기존 Next 셸과 Python AI 서비스를 사용한다. 대화는 브라우저 메모리에서 유지하고 앱 DB에 질문·답변을 저장하지 않는다. 답변 생성은 Codex CLI의 gpt-6.1-terra로 실행한다. 운영 MySQL과 Qdrant 쓰기·timer 등록·PR 머지는 개별 승인 대상이다. 5단계까지 intent 자동 수락을 적용했다. SEARCH-07·SHELL-03·A11Y-05·TRUST-14는 실제 운영 출시까지 미해결이다.

사용자가 요청한 로컬 임베딩은 운영 ARM64 CPU에서 확인한 다국어 E5-small로 제공한다. 인덱스 구축과 질문 검색의 임베딩을 서버에서 계산한다. 답변 생성은 기존 모델의 연결과 실제 응답 검증이 따로 필요하다.

## 열린 질문

없음. 운영 인덱스 쓰기와 머지는 검증된 대상과 실행 범위를 준비한 후 승인받는다.
