# 모두의입법 1차 수정 검증 기록

1차 수정은 목록·검색·단계/표결 표시·요약 접근성·다크 피드 탭을 대상으로 하며, 운영 배포 후 검증까지 결함 이슈를 유지한다.

- 기준: main `f3bb744`, 브랜치 `fix/ux-polish-round-one/claude`.
- 사용자 승인: 5단계까지 intent 자동 수락. 운영 DB 쓰기·timer 등록·PR 머지는 개별 승인 대상으로 유지한다.
- 운영 데이터 변경과 DB 마이그레이션은 이 변경에 포함하지 않았다.
- 실제 계정의 로그인 흐름은 2차 W7에서 재현한다.

## 자동 검증

| 검사 | 결과 |
| --- | --- |
| 웹 `npm run lint` | 통과 |
| 변경한 hooks·constants·store·types에 대한 추가 ESLint | 통과 |
| 웹 `npx tsc --noEmit` | 통과 |
| 웹 `npm test` | 63건 통과 |
| 웹 production `npm run build` | 통과 |
| Java 17 `./gradlew test bootJar --no-daemon` | 56건 통과, 실패·오류·skip 0 |
| 로컬 MySQL 8 실제 ngram FULLTEXT | 위 56건에 4건 포함. 관련도, 구두점, 끝 페이지, 개정안 정렬, LIKE 예약문자 검증 |

MySQL 테스트는 127.0.0.1의 전용 `lawdigest_polish` DB만 받도록 제한했다. `LAWDIGEST_MYSQL_TEST_URL`이 없으면 해당 4건은 실행하지 않는다. 운영 DB를 테스트 대상으로 사용하지 않았다. 백엔드에는 별도 Java lint task가 없어 이를 실행했다고 보고하지 않는다.

웹 빌드에는 기존 Tailwind ease 클래스 경고가 남는다. 로컬 Node 26의 localStorage 실험 경고도 관찰했다. 검색 저장소 제한·사용 불가 처리는 예외를 잡고 탐색을 계속한다.

## 실제 화면 확인

로컬 production 웹과 운영의 읽기 API를 연결했다. 새 백엔드의 native 검색과 개정안 페이지는 격리 MySQL·서비스/컨트롤러 테스트로 검증했으며, 운영 연결 검증은 배포 후에 진행한다.

| 조작 | 확인 |
| --- | --- |
| 의료법 검색 | 한국어 URL을 한 번 해석하고 올바른 제목·결과를 표시. 다음 페이지로 5건에서 10건 이상 증가. 운영 검색 API의 기존 크기 5는 백엔드 배포 후 10으로 변경됨 |
| 검색 Dialog | 입력 자동 포커스, Tab 이동 가두기, Esc 닫기와 진입 버튼 포커스 복귀, 배경 스크롤 잠금. 지우기를 눌러도 URL 유지 |
| 피드 | 법안 탭·정부이송 필터 URL 유지, 정부이송 43건까지 로딩 후 끝 상태 표시 |
| 의원 프로필 | 이해식 의원 대표발의 첫 10건, 공동발의 탭 URL `proposal=joint`, 추가 페이지로 30건 이상 증가 |
| 목록 → 상세 → 화면의 뒤로 가기 | 피드 정부이송의 누적 43건·필터 URL 유지, 약 27,747px 위치 복원. 의원 공동발의에서도 탭·목록과 약 3,156px 위치 복원 |
| 현재 검색어 수정 | 의료법 결과의 검색 입력 버튼을 열면 의료법으로 초기화하고 입력에 포커스 |
| 요약 | 복합 마크다운도 접힌 높이 288px로 제한. 펼치기 버튼의 aria-expanded 변경과 전체 내용 표시 |
| 정부이송 상세 | 표본 PRC_R2Q5P0P8V0U7T1Q3M3L6U5T5S5Y6X9의 현재 단계 STEP 05 |
| 375px 다크 화면 | 문서 폭 375px로 가로 넘침 없음. 피드 선택 탭 대비 16.68:1, 비선택 탭 9.06:1 |

CSS 뷰포트는 DOM의 innerWidth로 375px와 1440px를 확인했다. 1440px 검색 결과를 라이트·다크에서 확인했고 임시 뷰포트를 복원했다. 로컬 검증은 운영 완료 판정에 포함하지 않는다.

## 남은 작업과 승인 지점

- PR 머지 뒤 공식 배포 흐름에서 백엔드와 웹의 SHA·health를 확인하고 위 표의 같은 조작을 운영에서 재현한다. 확인한 결함만 이슈를 닫는다.
- RAG intent를 즉시 이어 진행한다. SEARCH-07·SHELL-03·A11Y-05·TRUST-14는 실제 출시까지 미해결이다.
- W1: 7월 이후 법안·분야·표결 백필과 수집 스케줄 복구. 운영 DB 쓰기와 timer 등록은 각각 승인받는다.
- W3 후속: 21대 폐기 상태·기본 22대 필터·파이프라인 상태 정합을 백엔드와 운영 데이터에서 검증한다.
- W7의 실제 계정 로그인 검증, W8의 운영 주체·연락처·보관 기준 확정은 남아 있다.
- 5단계의 7일 연속 timer 성공은 실제 관찰 기간을 충족한 뒤 판정한다.
