# 리포트 전용 피드 (FEED-01)

검증된 생성 결과를 별도 리포트 레코드로 저장하고 리포트 탭과 상세 화면에서 읽는다.

- 기존 생성 경로는 검증을 통과한 긴 리포트도 Bill의 AI 요약 필드에만 저장했다. 운영 피드와 현재 코드에서 리포트와 법안 탭이 같은 목록 쿼리를 쓰는 것을 재현했다.
- 검증 성공 시 리포트와 기존 법안 요약을 한 트랜잭션에서 저장한다. 오래된 재시도는 최신 리포트를 덮어쓰지 않는다. 일반 AI 요약 갱신은 기존 리포트를 보존한다.
- `GET /v1/reports`는 READY 법안에 연결된 리포트를 생성 완료 시각 순서로 반환한다. `GET /v1/reports/{billId}`는 같은 조건의 본문만 반환한다. 공개 시각은 생성기가 기록한 UTC 시각이다.
- 웹의 리포트 카드와 상세는 일반 법안 피드와 독립적으로 동작한다. 리포트 상세에서 관련 법안과 국회 원문을 열 수 있다. 빈 목록에는 법안 탭 링크를 제공한다.

## 검증

- 백엔드 61건과 bootJar, 웹 77건과 린트·프로덕션 빌드, AI 생성·저장 테스트 88건이 통과했다.
- 격리 MySQL에서 리포트 저장, 오래된 쓰기 거절, 일반 요약과 별도 보존, READY 필터·페이지 종료를 검증했다.
- 375px 다크 모드의 로컬 프로덕션 빌드에서 실제 운영 요약과 일치한 리포트 표본의 목록·상세·법안 탭 이동을 확인했다. 빈 목록과 없는 상세 HTTP 404도 확인했다.

## 운영 적용

1. 승인 뒤 `infra/db/migrations/20261103_create_bill_report.sql`을 적용한다. 운영 Bill 식별자와 같은 길이·문자셋·콜레이션을 사용한다.
2. 보관된 성공 manifest와 운영에 이미 공개된 READY 요약이 정확히 일치한 367건의 초기 적재 후보를 준비했다. 기존 시각을 보존하고 Bill 원문·요약을 다시 쓰지 않는다. 운영 DB 읽기 전용 사전 검증을 통과했다. 별도 승인 뒤 후보와 현재 값을 다시 대조하고 BillReport에 적재한다.
3. 백엔드·웹 적용 후 리포트 API, 리포트 피드, 상세와 원문 이동을 운영에서 확인한다. 이 기록의 검증 시점에는 운영 스키마와 데이터 변경을 실행하지 않았다.
