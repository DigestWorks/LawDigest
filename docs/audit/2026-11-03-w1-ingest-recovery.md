# W1 법안 수집 선행 복구 검증

11월 2일 법안 29건의 원문·발의자 처리 dry_run을 복구했으며, 운영 적재와 자동 수집은 개별 승인 뒤에 이어간다.

- 기존 코드: 후보 29건을 찾고도 `missing_proposer_relations`로 모두 제외, 304초, exit 1.
- 수정 코드: 29건 처리·거절 0건, 44초, exit 0. DB 반영 0건.
- 반복 적재에서 기존 AI 요약·제목·태그·조회수·생성일을 보존한다.
- 운영 DB를 읽어 대조한 결과, 필요한 의원 코드 139개 중 1개가 없다. 단건 의원 추가와 전체 명부 동기화를 구분했다.
- 사용자의 5단계까지 intent 자동 수락을 적용했다. PR 머지·운영 DB 쓰기·timer 등록은 각각 승인 대상이다.

## 다시 확인한 원인

기존 7월 법안은 BILLINFOPPSR API에서 발의자 14명을 반환한다. 같은 키로 조회한 11월 2일 최신 표본은 INFO-200을 반환하며, BILLINFODETAIL과 의원발의 목록 상세에도 없다. 반면 BPMBILLSUMMARY에는 원문 요약이 있고, 국회 의안정보시스템에는 법안 상세·명시된 대표발의자·전체 제안자 명단이 공개돼 있다. 키 장애로 단정할 수 없다.

API 응답이 비었거나 역할을 확인하지 못하면 공식 상세와 제안자 팝업을 보완 출처로 읽는다. 요청한 법안 ID·번호, 명시된 대표발의자, 전체 개수·페이지를 확인한다. 의원 명부에서 유일한 코드로 매칭하지 못하면 부분 명단을 적재하지 않는다. 첫 번째 공동발의자를 대표로 추정하던 처리는 제거했다.

추가로 확인한 표본은 다음과 같다.

- `PRC_T2U6T0O9P0N8N1M4N4L5L0U0S4S6Q8` / 2222388: 전체 10명과 대표발의자 허영 확인.
- `PRC_B13249EE9E27483E96C9B12CAB06A4` / 2222364: 전체 13명. 프로필이 아직 연결되지 않은 의원도 명단에 있다. 이름·한자명과 유일한 코드를 확인한다.
- 백승아의 공식 한자명은 `白承婀`, 의원 API는 `白承아`이다. 한자 필드가 불완전할 때 이름·정당으로 함께 확인한다. 온전한 한자명이 서로 충돌하거나 동명이인의 코드가 여럿이면 거절한다. 유니코드 호환 한자만 정규화한다.

## 재수집 보존과 의원 동기화

원문 수집의 AI 필드가 null·빈 문자열·공백이면 기존 AI 결과를 유지한다. 제목만 생성된 결과도 보존한다. 새 AI 결과가 명시된 갱신과 최초 적재는 유지한다. 조회수와 기존 생성일을 재설정하지 않는다.

의원 부분 upsert의 기본 동작은 전달된 의원만 추가·갱신하는 것이다. 다른 의원을 비활성화하지 않는다. `full_snapshot=True`는 API의 선언된 전체 건수·모든 페이지·코드 유일성을 확인한 전체 동기화에서만 지정한다. 빈 명부와 부분·중복 명부는 DB 연결 전에 거절한다. 신규 의원의 대수, 이름, 의원실·전화번호도 함께 저장한다.

## 검증 결과

| 검사 | 결과 |
| --- | --- |
| 변경 Python 파일의 Ruff F·E9 | 통과 |
| 관련 data 회귀 검사 | 105건 통과, DB 연결이 필요한 기존 6건은 건너뜀 |
| 전용 로컬 MySQL 8 검사 | 7건 통과. AI/제목/태그·조회수·생성일 보존, 명시적 AI 갱신, 의원 부분 추가와 전체 교체 검증 |
| 기존 코드로 같은 MySQL 보존 검사 | AI 요약이 null로 사라져 실패함을 재현 |
| Python sdist·wheel 빌드 | 통과. 새 파서 포함, 환경 파일 미포함 |
| 실제 11월 2일 후보 처리 | 29건 수집·29건 처리·거절 0, 44초 |
| 실제 의원 전체 명부 dry_run | 선언된 299건과 실제 299건 일치, 완료·전체 페이지 확인 |

data 전체 테스트를 통과했다고 보고하지 않는다. 검사는 변경과 연결된 수집·처리·DB·런타임·상태 동기화·검색 가시성 범위다. 기존 pandas/PyMySQL 폐기 예정 API 경고가 남는다.

실제 수집 검증은 운영 서비스와 분리한 임시 소스 복사본으로 실행했다. DB 연결 함수를 차단했고, 임시 소스의 디렉터리 깊이에 맞춰 artifact 저장 경로만 임시 경로로 지정했다. 마지막 의원 동기화 검증도 DB 연결을 차단했다. 별도로 수행한 운영 DB 대조는 읽기 전용 트랜잭션에서 조회하고 rollback했다.

## 운영 반영 전 확인할 대상

| 대상 | 확인한 값 |
| --- | --- |
| 법안 artifact | 29건, 모두 원문 요약 있음, 신규 법안 29건, 기존 DB 중복 0건 |
| 법안 artifact SHA-256 | `2b7b696f28a9aba5515d08996eb9111e5364864fe0b2cea56b8ea982a851a417` |
| 발의자 코드 | 139개 중 운영 DB에 1개 없음 |
| 누락 의원 | 김형연, KBZ59750, 조국혁신당, 22대 |
| 누락 의원 artifact SHA-256 | `5730fc93b4d14cbf89a5c951108b70f62aff44424e1d932dfb056ed982ef47b4` |

운영 쓰기 승인 전에 artifact 해시·개수와 운영 DB 상태를 다시 확인한다. 누락 의원을 부분 upsert로 추가한 뒤 법안 29건과 대표·공동발의 관계를 반영하는 범위를 제시해야 한다. 의원 전체 명부 교체로 대신하지 않는다. 이 표는 실행 승인이 아니다.

신규 법안은 원문 적재만으로 AI 요약이 생성되지 않는다. AI 요약·분야 분류·표결/상태 백필과 검색 문서 갱신을 후속 W1 작업으로 검증한다. 7월 이후 전체 백필, timer 등록, 7일 연속 성공도 남아 있다. 승인·배포·운영 화면 검증 전에는 #145와 관련 결함을 닫지 않는다.
