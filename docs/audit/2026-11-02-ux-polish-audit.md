## 1. 결론

모두의입법은 아직 사용자가 완성 제품으로 느끼는 상태가 아니다. 원인은 두 가지다.

- **데이터가 멈춰 있다.** 피드는 2026-07-09, 타임라인은 2026-03-27에서 멈췄다. 화면 어디에도 데이터 기준일이 없다. 사용자는 국회 활동이 없거나 서비스가 방치되었다고 판단한다.
- **핵심 경로가 깨져 있다.** 검색은 5건에서 멈추고, 한 글자나 괄호가 들어간 검색어는 오류 화면을 낸다. 의원·정당 프로필은 발의 법안을 3건만 보여 준다. 처리 단계는 일부 법안에서 틀리게 표시된다.

반면 AI 요약 문장, 정부안·위원장안 구분, 요약 렌더링 안전성, API 응답 속도는 이미 완성도가 높다. 폴리싱은 새 기능 추가가 아니라 기존 기능의 결함 제거와 신뢰 표시 보강으로 충분하다.

## 2. 감사 방법

| 단계 | 내용 |
| --- | --- |
| 현장 확인 | 운영 사이트 피드·상세·타임라인·탐색·로그인 화면을 데스크톱과 모바일(375px)로 열어 스크린샷 10장 확보 |
| 영역 감사 | 화면 영역 10개마다 감사 에이전트 1개. 코드 전체 열람, 운영 HTML·API GET 요청으로 근거 확보 |
| 반박 검증 | 영역마다 독립 검증 에이전트 1개가 각 결함을 다시 확인하고 반박 시도 |
| 누락 점검 | 첫 방문부터 재방문까지 사용자 여정을 따라가며 목록에 없는 결함 탐색 |
| 직접 재확인 | 보고자가 핵심 결함 8건을 운영 응답과 코드로 다시 확인. 8건 모두 재현 |

### 감사의 한계

- 반박 검증에서 315건 중 5건만 제외되었다. 검증이 관대했을 수 있다. 구현 전에 각 결함을 다시 재현한다.
- 같은 결함이 여러 영역에서 중복 보고되었다. 예를 들어 단계명 오타는 3건, 요약의 버튼 역할 문제는 3건으로 보고되었다. 고유 결함 수는 323건보다 적다.
- 로그인이 필요한 흐름(토큰 만료, 스크랩 상태, 알림, 탈퇴)은 실제 로그인으로 재현하지 않았다. 코드 근거로만 확인했다.
- 마지막 종합 단계는 사용자 요청으로 중단했다. 작업 묶음은 보고자가 직접 구성했다.

## 8. 유지할 강점

- AI 요약 본문이 시민 언어로 쓰여 있고, 굵게 표시와 용어 풀이가 이해를 돕는다.
- 요약 마크다운을 HTML 주입 없이 React 노드로 렌더하고 테스트로 고정했다.
- 정부 제출 법안과 위원장 대안을 의원 발의와 구분해 보여 준다.
- 피드와 검색 결과 첫 화면이 서버에서 렌더되어 검색엔진이 내용을 읽을 수 있다.
- 운영 API 응답이 빠르다. 피드는 약 0.12초, 일반 검색은 0.1~0.5초다.
- OAuth 성공 처리기가 리다이렉트 주소를 허용 목록과 대조한다. 리프레시 토큰 쿠키는 HttpOnly·Secure다.

감사자가 기록한 강점 87건 전체는 결함 전체 목록 문서 끝에 있다.
