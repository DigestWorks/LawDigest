# 법안 질의응답 구현·검증 기록

근거 원문을 확인하는 질문 API와 기존 셸의 질문 화면을 구현했으며, 실제 모델 성공·전체 운영 인덱스·운영 출시는 추가 검증이 필요하다.

- 1차 PR #153의 화면·검색 수정을 기반으로 하는 후속 작업이다. intent → spec → plan을 각각 커밋했고 5단계까지 intent 자동 수락을 적용했다.
- 기본 자료는 22대이고 21대·전체를 선택할 수 있다. 수집된 처리 결과와 근거 원문·국회 링크를 함께 제공한다.
- 답변의 문단별 출처를 검증하고 검색 원문을 현재 DB와 다시 대조한다. 자료 부족과 서비스 오류를 구분한다.
- 질문 화면은 검색 Dialog에서 연결한다. 운영 설정과 인덱스가 준비된 경우에만 진입점을 노출한다.
- SEARCH-07·SHELL-03·A11Y-05·TRUST-14는 실제 출시 검증까지 미해결로 유지한다.

## 구현 범위

Python AI 서비스가 임베딩·Qdrant 검색·읽기 전용 MySQL 대조·구조화 생성을 맡는다. Next의 공개 프록시를 통해 질문을 받고 내부 서비스는 루프백과 인증 토큰으로 제한한다. Java API 책임은 추가하지 않았다.

원문 해시는 검색에 사용한 법안명·원문·대수·발의일을 포함한다. 변경된 원문 청크는 생성에 사용하지 않는다. 처리 단계·결과는 매 요청 현재 DB에서 읽으므로 상태 갱신과 AI 요약 변경만으로 검색 근거를 버리지 않는다. 이전 대화의 AI 답변을 사실 근거로 재사용하지 않는다.

생성은 `gpt-4o-mini`의 Responses 구조화 출력으로 받으며, 완료 여부·유효한 출처 ID·문단의 근거를 확인한다. 원문을 찾지 못하면 생성 호출을 건너뛴다. 제공자 실패·거절·불완전 응답을 정상 답변 문자열로 바꾸지 않는다. 인용 ID 검증만으로 설명의 의미 정확성을 보장하지 않으며 실모델 원문 대조가 남아 있다.

질문은 2~1,000자, 이전 질문 4개, 출처 ID는 질문마다 최대 8개, 공개 요청 본문은 최대 32KiB다. 동시·익명·일일 요청 한도를 두고 실패한 생성도 계산한다. 취소한 요청의 늦은 응답이 재시도한 대화를 덮어쓰지 않도록 요청 단위로 대조한다. 질문·초안·답변은 Jotai 메모리에만 두며 새로고침하면 사라진다.

인덱스 명령의 기본값은 dry_run이다. 전체 READY 원문 스냅샷·해시를 확인하고 새 버전 컬렉션에만 적재한다. 구축 도중 실패하면 기존 별칭을 유지하며, 전량·스키마·모델 검증 뒤에만 별칭을 전환한다. 부분 표본과 기존 실험 인덱스를 출시 전체 자료로 활성화하지 않는다.

## 실제 화면 확인

운영에서 읽은 공개 법안 표본 4건을 로컬 메모리 인덱스에 넣고, 고정 응답임을 본문에 명시한 전용 API로 화면을 확인했다. 모델 호출 성공이나 실제 답변 품질을 대신하는 증거로 사용하지 않는다.

- 모바일 CSS 폭 375px·다크 모드에서 질문·대기·실패·재시도·중지와 대수 선택을 확인했다. 문서·본문 폭이 375px를 넘지 않는 것을 확인했다.
- 1440px 데스크톱에서 질문 화면과 검색 Dialog의 질문 진입·닫힘을 확인했다. 답변은 질문 위치에서 읽도록 유지하고 최신 답변으로 이동하는 버튼을 제공한다.
- 근거 법안 상세의 최종 렌더와 뒤로 가기 뒤 대화·초안 복원을 확인했다. 전역 로딩 화면이 일시적으로 500 에러 이미지를 표시하는 기존 W9 결함도 재현했다.
- 21대 표본의 `임기만료폐기` 결과가 근거 카드에 표시되는 것을 확인했다.
- 한글 조합 중 Enter와 취소 응답 경합은 자동 회귀로 확인했다. 실제 계정 인증 경로의 검증은 W7·W8에서 진행한다.

상세 화면 왕복 검사에서는 로컬 읽기 전용 API 프록시로 조회수 PATCH를 차단했다. 그 프록시와 고정 응답 코드는 테스트용 임시 파일이며 제품에 포함하지 않는다. 운영에 배포하는 인덱스는 전체 원문 절차를 다시 통과해야 한다.

## 출시 전 남은 일

1. 실제 제공자 요청을 정상화한 뒤 공개 법안·무관 질문·후속 질문·21대 범위의 답변을 원문과 직접 대조한다.
2. PR #153과 이 후속 변경의 머지 승인을 각각 받고 main 기준을 확인한다.
3. 전체 원문 스냅샷의 대수별 건수·청크 수·해시·대상 컬렉션을 제시하고 Qdrant 쓰기 실행 승인을 받는다.
4. [RAG 운영 절차](../../deploy/PROD_RAG_DEPLOY.md)에 따라 인덱스·API·웹을 반영하고 운영 화면을 검증한다.
5. 운영 검증 뒤 관련 결함을 갱신한다. W1의 전체 백필과 인덱스 갱신도 이어 확인한다.
