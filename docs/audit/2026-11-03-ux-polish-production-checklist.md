## 운영 로그인 진입 확인

운영 로그인 페이지에서 세 제공자 버튼을 직접 눌렀다. 인증 시작 API는 각 제공자로 HTTP 302 응답을 보내고 `https://api.lawdigest.kr/v1/login/oauth2/code/` 아래에 제공자 이름을 붙인 콜백을 전달했다.

- 운영 Google 로그인 버튼을 눌러 `400 redirect_uri_mismatch`를 재현했다. 시작 API는 프로젝트 번호 `264615857118`로 시작하는 클라이언트와 운영 API 콜백을 전달한다. 해당 프로젝트를 Google Cloud 콘솔에서 지정하자 현재 계정에 추가 액세스가 필요하다고 표시됐다. 프로젝트 관리자가 승인된 콜백을 확인해야 한다. [Google 오류 안내](https://developers.google.com/identity/protocols/oauth2/web-server#authorization-errors)
- 네이버는 계정 입력 전 모두의입법 서비스 오류를 표시했다. 운영 앱의 서비스 URL·콜백 등록값·상태를 개발자센터에서 확인한다. [네이버 개발 가이드](https://developers.naver.com/docs/login/devguide/devguide.md)
- 카카오 로그인 폼에서 계정·비밀번호 입력란을 확인했다. 서비스 복귀와 세션 검증은 실제 계정 인증이 필요하다.
- 세 제공자의 운영 OAuth 시작 요청과 취소 응답 경로를 비인증 상태에서 대조했다. 취소 응답의 HTTP 302는 모두 운영 웹 콜백에 오류를 전달했다. Google 웹 콜백은 취소 안내 없이 로그인 화면으로 돌아갔다. 실제 제공자 인증과 취소는 별도 검증한다.
- 인증 전 실패 콜백이 설정된 웹 출처만 사용하도록 4차 후보를 보완했다. 허용된 콜백과 기본 경로, 잘못된 출처와 URL 형식, 실제 Spring 콜백 경로를 검사했다.
- 테스트 웹 로그인은 HTTP 502였고 테스트 프로필의 콜백 호스트는 DNS NXDOMAIN이었다. [테스트 로그인 복구 #164](https://github.com/DigestWorks/LawDigest/issues/164)
- 서버에서 테스트 3020 리스너와 PM2 항목이 없고 기존 테스트 release 심링크가 남아 있었다. 운영·개발 웹의 로컬 로그인은 HTTP 200이었다. 원격 dev `887efce`로 문서의 테스트 배포 스크립트를 실행했고, App Router에 영향을 주는 구형 Next.js 14.0.2를 확인해 활성화 전에 중단했다. 공개 테스트 로그인은 여전히 502다. GitHub 비교에서 dev는 운영 main `dcb2ae2`의 조상이며 336커밋 차이다. dev 갱신 범위를 [초안 PR #165](https://github.com/DigestWorks/LawDigest/pull/165)에 기록했다. [Next.js 보안 공지](https://nextjs.org/blog/security-update-2025-12-11) · [dev와 main 비교](https://github.com/DigestWorks/LawDigest/compare/dev...main)
- 운영 nginx의 `api.lawdigest.kr`은 `test_backend` upstream을 통해 808 포트로 연결된다. 컨테이너명은 `lawdigest-backend-test`이고 활성 Spring 프로필은 `prod`이며 헬스 응답은 200이다. 테스트 API에는 별도 런타임과 테스트 DB 연결이 필요하다. 테스트 프로필의 콜백 호스트와 `.lawdigest.kr` 쿠키 범위도 테스트 로그인 전에 확인한다.
